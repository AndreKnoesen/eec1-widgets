ENG 6 Cumulative Assessment: Practice Study Guide

Assessment Structure and Grading

The assessment has two stages. Stage 1 is required; Stage 2 is optional.

Stage 1 — Week 8 (Tuesday–Thursday, before Memorial Weekend)
A 50-minute proctored session in MATLAB Grader. The assessment covers lectures 1 through 10 (see the Lecture Essentials document for the detailed topic breakdown per lecture). The one exception is Lecture 9 (GUI): you will not be asked to create a graphical user interface. The format is otherwise the same as other assessments in the course.

Two submission attempts per problem. First-attempt feedback is visible; use it to refine your work before your second submission. Full credit is available on both attempts. The last submission is the one that is graded.

The assessment is closed book with no notes. MATLAB documentation is available inside the lockdown browser. While you may see an indication of your score at the end of the session, final grades are determined on Friday.

Stage 2 — Finals Week (Optional Retake)
A different, cumulative exam covering the original 6 lectures plus Weeks 8–9 material in equal proportion. One submission attempt, no feedback. Maximum score: 80%. Sign-up required one week in advance.

Final grade = the higher of your two scores (80% cap applied to Stage 2 only). Taking the retake cannot lower your grade.

There is no compulsory final.

What the Assessment Looks Like

The assessment is fifty minutes long, one hundred points total. It has three sections:

Section A. Five multiple choice questions, twenty-five points. Three OOP items (about classes, value vs handle behavior, public vs private access) and two conceptual probes (about floating-point comparison and short-circuit evaluation). Each question has four answer options. Canvas shuffles the answer order, so the position of the correct answer varies for each student.

Section B. Three short coded problems in MATLAB Grader, fifty points total. Each problem is a function with a clear specification and three to five test cases. You write the body of the function. The function signature, doc comment, and a placeholder line are pre-filled in the editor.

Section C. One longer integrative problem in MATLAB Grader, twenty-five points. The function involves input validation, a multi-step computation, and an edge-case contract. Same editor format as Section B.

A student who knows the material well should pass Sections A and B comfortably and earn the seventy-five percent threshold from those alone. Section C is where strong students push from the C+/B- range into the higher grades.

Logistics on Exam Day

Arrive at least ten minutes before the scheduled start time; check-in begins ten minutes before the assessment opens. Bring nothing extra to the exam. No additional materials are permitted. All personal items, including cellphones, must be left at the front of the room.

Develop and test your code in the MATLAB live environment before you paste it into MATLAB Grader. This is the single most important strategic point in this document. Read it twice. The MATLAB Grader window inside the lockdown browser is for verification, not development. By the time you press Submit, you should already know your function works.

When you submit a coded problem, MATLAB Grader runs every test independently and shows you the result of each one. The test names tell you what each test is checking (for example, "below threshold", "boundary value", "non-finite input", "validation, non-numeric data", "no qualifying columns"). Nothing is hidden; you see exactly which tests passed and which failed.

The grading rule is that your last submission counts. If you submit a first version that passes most tests, then edit and submit a second version that breaks something, the second version is what gets graded. Even if it scores lower. Even if you panicked and just wanted to try one more thing.

In practice this gives you exactly one useful submission plus one final submission. If you treat MATLAB Grader as a development environment and iterate inside it, you will burn your first attempt on discovery and have only one chance to fix what you found. If you treat it as verification, you submit once, you see the test results, and you only submit a second time if you are genuinely confident the fix improves the score.

The workflow:

  1. Read the problem statement carefully in the lockdown browser.
  2. Open MATLAB (the live environment is available in the lockdown browser alongside MATLAB Grader). Write your function there. Try it on a few sample inputs in the command window. Verify outputs by hand for at least one case.
  3. Use the documentation viewer when you need to look up a function. The full MATLAB documentation is inside the lockdown browser; the AI assistant is not.
  4. When your function works in MATLAB, paste it into MATLAB Grader and submit.
  5. Read the test results. If a test failed, the test name tells you what was checked. Decide whether you understand the failure well enough to fix it. If yes, fix in MATLAB first, retest, then submit. If no, leave the first submission as your final answer.

The trap to avoid: do not submit the same problem more than twice. A third submission overwrites the second. Submit, observe, decide. If you really did improve the code, submit. Otherwise, walk away.

The assessment runs in a lockdown browser. Inside that browser you have access to the MATLAB live environment, MATLAB Grader, and the full MATLAB documentation. The MATLAB AI assistant (Copilot) is blocked. Other browser tabs, notes, and external resources are blocked. Plan to use the documentation; it is there for you.

Time. Fifty minutes total. The exam is designed so a prepared student finishes in about forty minutes, leaving ten minutes of buffer for documentation lookups, MATLAB-side testing, and any last edits.

How to Use This Document

This is not a practice exam. It is a guided walk through the patterns the assessment will test. Each worked example below shows a small problem, a complete solution, and a paragraph explaining why the solution looks the way it does. The live exam will ask you to recognize these same patterns in problems you have not seen, with different surface stories and slightly different shapes.

If you can read each worked example, close the document, and reproduce the solution from scratch in MATLAB, you are well prepared. If you cannot, that is the exact area to study before the exam.

The Lecture Essentials document and the Fundamental Concepts Mindmap are your reference companions. This document points to the patterns; those documents explain the underlying concepts in depth.

Worked Example 1: Predict the Output (Floating-Point)

Mindmap Node 2: data and types.

What does the following MATLAB code print?

a = 0.1 + 0.2;
if a == 0.3
    disp('match')
else
    disp('no match')
end

Answer: no match.

Why. In IEEE 754 double precision, the decimal values 0.1, 0.2, and 0.3 cannot be represented exactly in binary. The stored approximations of 0.1 and 0.2 sum to a value that is slightly different from the stored approximation of 0.3. The == operator compares the exact bit patterns and returns false.

The reliable replacement on computed floating-point values is a tolerance comparison:

if abs(a - 0.3) < 1e-9
    disp('close enough')
end

The Section A MCQs include items in this style. Reading code that uses == on a computed float and predicting the result is a routine question.

Worked Example 2: Filter Then Reduce with an Empty Guard

Mindmap Node 4: combining pieces; Node 7: robustness.

Write a function that takes a vector of student scores and returns the average of the passing scores (those greater than or equal to 60). Return zero if no scores pass.

function avg = passingAverage(scores)
    passing = scores(scores >= 60);
    if isempty(passing)
        avg = 0;
    else
        avg = mean(passing);
    end
end

Why this shape. The first line is a filter: a logical expression scores >= 60 produces a mask the same size as scores, and the indexed assignment scores(...) returns just the elements where the mask is true. The isempty check is the empty-result guard: mean of an empty vector returns NaN, which is rarely what the caller wants. Returning a documented safe default (zero) is the kind of contract design the assessment expects.

The Section C integrative problem uses this same filter-then-reduce-with-empty-guard structure on a 2-D matrix instead of a 1-D vector. The shape is bigger but the logic is the same.

Worked Example 3: Multi-Way Branching with Boundaries

Mindmap Node 5: decisions; Node 7: edges.

Write a function that takes a temperature in degrees Celsius and returns a label: "freezing" if below 0, "cold" if at or above 0 but below 15, "moderate" if between 15 and 25 inclusive, "warm" if above 25 but at or below 35, "hot" if above 35. Return "invalid" if the input is not finite.

function label = classifyTemperature(tempC)
    if ~isfinite(tempC)
        label = "invalid";
    elseif tempC < 0
        label = "freezing";
    elseif tempC < 15
        label = "cold";
    elseif tempC <= 25
        label = "moderate";
    elseif tempC <= 35
        label = "warm";
    else
        label = "hot";
    end
end

Why this shape. A multi-way exclusive branching problem is solved with one if/elseif/else chain, not multiple independent if blocks. The not-finite case must come first, before any arithmetic comparison, because NaN < 0 and NaN < 15 and similar comparisons all return false, which would silently fall into the else branch and produce a wrong label.

Notice the boundary semantics. The specification says the moderate range is inclusive on both ends (15 to 25), warm is exclusive low and inclusive high (above 25, at or below 35). The code reflects that: tempC <= 25 for the moderate branch and tempC <= 35 for the warm branch. Choose your < and <= carefully and read the specification carefully.

The Section B branching problem uses the same control-structure pattern with different threshold semantics. Read the boundary rule each time you write one of these; do not assume.

Worked Example 4: Position Recovery from a Predicate

Mindmap Node 3: addressing positions.

Write a function that takes a vector of measurements and a threshold, and returns the position of the first measurement that is strictly greater than the threshold. Return -1 if no measurement exceeds the threshold.

function pos = firstAbove(measurements, threshold)
    above = measurements > threshold;
    indices = find(above);
    if isempty(indices)
        pos = -1;
    else
        pos = indices(1);
    end
end

Why this shape. A predicate over a vector produces a logical mask. To get the positions of the elements that satisfy the predicate (rather than the values), use find. The result is a vector of indices in ascending order; the first one is the position of the first match. The empty case (no matches) is handled with the same isempty guard as Worked Example 2.

The Section B top-N problem uses this same pattern with one extra step: after finding the matching positions, sort them by some other criterion. The single-output version above is the cleanest demonstration of position recovery.

Worked Example 5: Validation Prologue and Multi-Output Function

Mindmap Node 6: function packaging; Node 7: defensive programming.

Write a function that takes a vector and returns three counts: how many elements are positive, how many are negative, how many are exactly zero. If the input is not a numeric vector, return -1 for all three counts.

function [pos, neg, zero] = countSigns(values)
    if ~isnumeric(values) || ~isvector(values)
        pos = -1;
        neg = -1;
        zero = -1;
        return
    end
    pos = sum(values > 0);
    neg = sum(values < 0);
    zero = sum(values == 0);
end

Why this shape. The validation prologue uses a sentinel-return contract: instead of throwing an error, the function returns documented invalid values that the caller can detect. This is the pattern the assessment uses everywhere; do not use error() calls because the autograder treats those as failures rather than as a contract.

Each count is a sum of a logical mask. values > 0 produces a mask the same size as values; sum on a logical mask returns the count of true entries. This is the cleanest one-line filter-and-count.

Note the multi-output signature [pos, neg, zero] = ... and the use of return to exit the function early after the validation failure. Both patterns appear in Section C of the assessment.

NaN Essentials

Mindmap Node 2: data and types; Node 7: edges and missing values.

NaN handling appears in roughly a third of the graded tests across Sections B and C. The rules are short but non-obvious, and a student who is solid on every other concept can lose real points by missing them. Learn these four facts cold.

1. Comparisons involving NaN are always false.

Every comparison operator (==, ~=, <, <=, >, >=) returns false when either operand is NaN. In particular, NaN == NaN is false. The practical consequence: an expression like find(x > threshold) silently excludes positions where x is NaN, because the comparison there is false. That can be exactly what you want, or it can hide a bug. Know which case you are in.

2. NaN propagates through arithmetic.

Any operation that touches NaN produces NaN: 1 + NaN, 0 * NaN, NaN / 5. If a single element of an aggregate input is NaN, the result of the aggregate is NaN unless you tell MATLAB otherwise.

3. isnan and isfinite answer different questions.

isnan(x) returns true only for NaN. isfinite(x) returns true only for ordinary numbers, that is, not NaN, not +Inf, and not -Inf. If your specification says "valid value" or "finite value", isfinite is the right predicate. If it says "missing value", isnan is the right predicate. Read the spec; pick the right one.

4. Aggregations accept an 'omitnan' option.

mean, sum, min, max, std, median, and similar functions accept 'omitnan' as a final argument. With that option they ignore NaN values in the input rather than propagating them. For matrices, the form is mean(M, 1, 'omitnan'): operate down columns (the 1), ignore NaN. Without 'omitnan', a single NaN anywhere in the input produces NaN in the output. One edge case to remember: if a column or vector is all NaN, then mean(x, 'omitnan') still returns NaN, because there are no values to average.

You will see all four of these come up in the assessment. The Section C integrative problem in particular relies on points 2 and 4.

Two Additional Specifics

1. MATLAB's sort is stable.

When two elements compare equal, sort preserves their original relative order. The permutation index that sort returns will pair each tied value with the earliest position it came from. The assessment exercises this: when ties exist among the top values, the expected position output is the one that pairs each tied value with the earliest original index. Your natural solution path will produce this for free. Do not add extra "tie breaking" logic on top.

2. The autograder is strict about shape, including for empty results.

MATLAB has more than one kind of empty array. [] is a 0x0 double; zeros(1,0) is a 1x0 row vector. The autograder uses isequal, which treats them as different. When a test expects an empty result, the shape has to match.

You usually do not have to think about this. If you write the algorithm in the natural way, your empty-output shape will match what the test expects. The trap is when you try to "help" by hand-coding the empty case: writing topVals = [] as a defensive default at the top of your function, or substituting [] for an empty value the natural path already produced, can give you a 0x0 where the test expects 1x0. Trust the natural path. If the specification's empty-case prose is satisfied by what your code already returns, do not change it.

What This Guide Does Not Cover

OOP coding. The Section A MCQs include three OOP questions about classdef behavior. Those test concepts you practiced in the team project; you should be able to read a small classdef and predict what a sequence of method calls produces. Mini-Project 4 is the best preparation for those items.

Specific live-exam problem statements. The live exam uses different domains, different variable names, and different specific problem shapes than these worked examples. The patterns are the same; the surface is different.
