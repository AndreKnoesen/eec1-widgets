19.11 Name-value arguments

Motivation

When a function has more than two or three optional inputs, positional
calls become hard to read. Consider a function that plots a signal with
options for color, line width, marker, and title. A positional call
might look like:

plotSignal(t, y, "red", 2, "o", "Demo")

A reader cannot tell at a glance which number is the line width and
which is the marker size. Worse, if a caller wants to set only the
title, they still have to fill in every preceding argument with a
placeholder.

Name-value arguments solve this by associating each value with a
name. The caller specifies only the options they care about, in any
order, and each value is paired with a meaningful name in the call.

Declaring name-value arguments

Inside a function, an arguments block declares the inputs. Required
and optional positional inputs are listed first. Name-value inputs are
gathered into a structure whose name appears in the function signature.

function plotSignal(t, y, opts)
    arguments
        t                (1,:) double
        y                (1,:) double
        opts.Color       string         = "blue"
        opts.LineWidth   (1,1) double   = 1
        opts.Title       string         = ""
    end

    plot(t, y, Color=opts.Color, LineWidth=opts.LineWidth)
    title(opts.Title)
end

Three points to notice:

  1. The name opts is just an identifier chosen by the function author.
    You could use nv, options, kw, or anything else. Inside the
    function, opts is a structure with one field for each
    name-value input.
  2. Each name-value input is given a default value with =. If the
    caller omits the argument, the default is used.
  3. The size and type specifications such as (1,:) double are optional
    but catch mistakes early and document the function's expectations.

Calling the function

Two equivalent syntaxes are accepted.

Equals form (recommended for new code):

plotSignal(t, y)                              % all defaults
plotSignal(t, y, Color="red")                 % one option
plotSignal(t, y, LineWidth=2, Color="red")    % any order, any subset

Comma form (used in older code and required in some legacy contexts):

plotSignal(t, y, "Color", "red")
plotSignal(t, y, "LineWidth", 2, "Color", "red")

Both produce the same result. The function definition does not change
based on which syntax the caller chooses.

Three rules to remember

Rule 1. Name-value arguments come last. All positional arguments
must appear before any name-value pair. This call is an error:

plotSignal(Color="red", t, y)   % invalid: name-value before positional

Rule 2. Order does not matter among name-value pairs. These two
calls do the same thing:

plotSignal(t, y, Color="red", LineWidth=2)
plotSignal(t, y, LineWidth=2, Color="red")

Rule 3. Names must be valid identifiers. A name-value argument
called allow-empty works with the comma form "allow-empty", true
but not with allow-empty=true, because the equals form requires the
name to be a legal MATLAB variable name.

Why this style is worth learning

Most built-in MATLAB plotting and analysis functions accept name-value
arguments (plot, histogram, xline, legend, scatter, and many
others). Writing your own functions the same way makes them:

  • Readable. Each value is labeled at the call site.
  • Order-independent. Callers do not have to memorize argument
    positions.
  • Extensible. New options can be added later without breaking
    existing callers, because old calls simply omit the new argument and
    receive the default.

Section summary

  • Name-value arguments associate a value with a name at the call site.
  • They are declared inside an arguments block, gathered into a
    structure such as opts.
  • Each name-value argument should have a default value.
  • They are called using either Name=Value or "Name", Value.
  • Name-value arguments must follow all positional arguments.

Participation Activity 19.11.1 (concept check)

Given this function definition:

function plotSignal(t, y, opts)
    arguments
        t                (1,:) double
        y                (1,:) double
        opts.Color       string         = "blue"
        opts.LineWidth   (1,1) double   = 1
        opts.Title       string         = ""
    end
    plot(t, y, Color=opts.Color, LineWidth=opts.LineWidth)
    title(opts.Title)
end

Which of the following calls are valid? For each invalid call, identify
the rule that is violated.

# Call Valid?
a plotSignal(t, y)
b plotSignal(t, y, "red", 2)
c plotSignal(t, y, LineWidth=2)
d plotSignal(LineWidth=2, t, y)
e plotSignal(t, y, Title="Run 1", Color="green")
f plotSignal(t, y, Color="green", LineWidth=1.5, Title="Run 2")

Answer key:

  • (a) Valid. All name-value arguments use their defaults.
  • (b) Invalid. "red" and 2 are passed positionally, but only t
    and y are declared as positional inputs.
  • (c) Valid. Only LineWidth is specified; the rest use defaults.
  • (d) Invalid. A name-value argument appears before positional
    arguments. Rule 1.
  • (e) Valid. Order among name-value pairs is free.
  • (f) Valid.

Participation Activity 19.11.2 (code completion)

Goal. Write a function summarize(x, opts) that returns the mean
of vector x, with two name-value options:

  • Trim: a fraction of values to drop from each end of the sorted
    vector before averaging. Default 0.
  • Round: the number of decimal places to round the result to.
    Default 2.

What is given. The function signature and the arguments block
are written for you. Your task is to fill in the function body so the
sample calls below produce the expected results.

function m = summarize(x, opts)
    arguments
        x          (1,:) double
        opts.Trim  (1,1) double = 0
        opts.Round (1,1) double = 2
    end

    % ----- YOUR CODE HERE -----
    % 1. Sort x in ascending order.
    % 2. Drop floor(numel(x) * opts.Trim) values from each end.
    % 3. Compute the mean of what remains.
    % 4. Round the result to opts.Round decimal places.
    % 5. Assign the result to m.

end

Sample calls and expected results. Use these to check your
function:

summarize(1:10)                       % expected: 5.50
summarize(1:10, Round=0)              % expected: 6
summarize([1 2 3 4 100], Trim=0.2)    % expected: 3.00  (drops 1 and 100, averages 2,3,4)

Answer key:

function m = summarize(x, opts)
    arguments
        x          (1,:) double
        opts.Trim  (1,1) double = 0
        opts.Round (1,1) double = 2
    end

    xs      = sort(x);
    n       = numel(xs);
    k       = floor(n * opts.Trim);
    trimmed = xs(1+k : n-k);
    m       = round(mean(trimmed), opts.Round);
end

Note on older MATLAB code

When reading MATLAB code from textbooks, online examples, or legacy lab
scripts, you may see functions that handle optional inputs using
varargin and manual parsing, or using the inputParser class. These
older patterns achieve the same goal but require more code and are less
self-documenting. The arguments block is the preferred style for new
code.
