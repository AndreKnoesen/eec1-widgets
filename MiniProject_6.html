MiniProject 6: Building Your First Activity Classifier

Your phone already does this. Apple Watch, Fitbit, and Google Fit all detect when you switch from walking to running to climbing stairs, without you pressing anything. They do it by training a classifier on labeled sensor recordings: data where someone wrote down what they were doing at the time of collection.

In Lab 11, without realizing it, you did exactly that. You recorded accelerometer data and encoded the label directly in the filename: walk_, run_, jump_. Every student in the class did the same. The result is a labeled dataset of several hundred recordings across three activities, collected on real phones by real people.

In this lab you will build the pipeline that processes that dataset, derive activity thresholds directly from the data rather than guessing them, and find out how accurately peak acceleration alone can identify what someone was doing. Where the classifier fails is at least as interesting as where it succeeds.

Background: The Dataset, the Pipeline, and the ML Connection

Read before starting Problem 1

The dataset. After all Lab 11 sections close, the TA assembles every submitted .mat file into a shared list. Running class_files.m defines files: a string array of filenames, one per recording. The exact count depends on how many students submitted valid files; your TA will confirm the expected totals.

Filename convention. Every file follows this pattern:
activity_firstname_lastname_section.mat
Examples: walk_jane_smith_a03.mat · run_john_doe_b01.mat · jump_ali_hassan_b02.mat

What each file contains. Each .mat file holds one variable data: an N×4 matrix with columns [Ax, Ay, Az, t] (three axes of acceleration in m/s², time in seconds at 100 Hz).

Why this dataset is special. In most sensor data problems, you have measurements but no ground truth: you have to guess or manually review what was happening. Here, every filename is a verified label: the person who recorded it declared the activity at the moment of collection. A dataset where every example has a known correct answer is called a labeled dataset, and it is the starting point for supervised machine learning.

The pipeline you are building today maps directly onto the ML workflow:
Raw files → getActivity labels: "walk", "run", "jump" → computeRecord features: peak, num_events, duration → buildResultsTable dataset: one row per recording → Part 4 classifier: derive boundaries, measure accuracy
Problems 1-3 build the infrastructure. Part 4 is where the analysis happens.

Problem 2: computeRecord

The second step is feature extraction: computing a compact numerical summary from each raw recording. A feature is a number you extract from raw data because you believe it carries information about what you want to classify. Here, the key feature is peak resultant acceleration.

Write a function that processes one recording and returns a struct. Include your getActivity solution as a local function at the bottom of the file. The skeleton and submission link are in the MATLAB Grader assignment.

The result struct must have exactly five fields:

Problem 2:computeRecord
Field Type Value
.filename string same as the filename input
.activity string the ground-truth label, extracted using getActivity
.peak double max of R = sqrt(Ax^2 + Ay^2 + Az^2) (the key feature)
.num_events double number of samples where R > threshold
.duration double t(end) - t(1) in seconds

Part 4: Derive and Evaluate Your Classifier

With the full dataset in a table, you can now act like an ML engineer. The labeled data tells you where each activity actually lives in feature space. Use that information to set thresholds, build a classifier, and find out how well peak acceleration alone can distinguish activities, then locate your own recordings in the results.

Open the mp6_part4.m script you saved to MATLAB Drive during Setup.

Before running it, open the script and read it. It is divided into five clearly labeled steps; make sure you can answer these questions for each step before you execute anything:

Part 4: Derive and Evaluate Your Classifier
Step What the code does Question to answer
Step 1 Computes mean, std, min, max of peak for each activity Why do we look at the spread (std) and not just the mean?
Step 2 Sets a decision boundary at the midpoint between adjacent class means Why the midpoint? What assumption does that make about the two groups?
Step 3 Assigns a predicted label to every recording based on its peak What does it mean for a recording to fall on the wrong side of a boundary?
Step 4 Counts correct predictions overall and per activity Why might overall accuracy hide something that per-activity accuracy reveals?
Step 5 Finds your own rows in the table and checks each prediction What would it mean physically if one of your recordings is misclassified?
